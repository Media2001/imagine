# Sources et limites A-25

Consultation officielle du 26 novembre 2026 ; les API réellement installées sont aussi qualifiées et empreintées dans `standard.json`, pas supposées à jour à partir du web.

- https://developer.wordpress.org/reference/classes/wp_comment/ — propriétés natives de commentaire utilisées : date GMT, état, présence email/IP et `user_id`. L'objet natif est employé, jamais une réinterprétation des valeurs de contenu.
- https://woocommerce.github.io/code-reference/classes/WC-Order.html — `get_customer_id`, `get_date_created`, `get_type`. Le magasin autoritaire est interrogé par `OrderUtil`; SQL sert uniquement à énumérer tous les IDs, y compris les états non enregistrés/corbeille, puis les getters natifs donnent la sémantique. Aucun rapprochement par email.
- https://developers.fluentforms.com/database/ — magasin des entrées `fluentform_submissions`, date `created_at`, charge `response`; choix de cet unique adaptateur car le schéma est documenté par l'éditeur. Les sous-tables de détails ne sont pas des entrées supplémentaires. Les brouillons Pro et les autres schémas répondant au détecteur structurel restent sous `autre` : pas d'affirmation d'exhaustivité.
  - **Consultation web effective le 26 novembre 2026**, dans le navigateur, section `fluentform_submissions` : phrase exacte **« Storing the form submissions »**. Dans la table de cette même section, ligne exacte (colonnes séparées par une tabulation) : `created_at\ttimestamp NULL` (la cellule Comment est vide). La phrase justifie le magasin d'entrées ; la ligne du schéma, et non une phrase inventée, justifie la colonne de date. Extrait vérifié et provenance : `fluentforms-source.json`. L'extraction directe était indisponible et la requête HTTP simple a renvoyé 403 ; le contenu courant a bien été lu dans le navigateur officiel, pas reconstitué depuis une source tierce.
- `wp/outils/staging/lib.php` : moteur inchangé, boucle de transformation §commentaires, affectation de l'email et effacement de l'IP/contenu ; tables inconnues gardées selon décision. `neutralise.php` exerce vraiment neutraliser puis anonymiser sur une copie de la base fictive. Aucun contenu n'est publié par ce témoin.
- `wp/outils/bascule/stream_guard.py`, `a11/Runtime.php`, `a11/ReadOnlyDb.php`, `a12/confine.py` : sources communes importées sans modification ; dépendances exactes scellées par les reçus. Les fonctions du gardien A-22 supervisent les deux flux ; le lot n'en duplique pas l'implémentation.

Le schéma Fluent Forms est reproduit de façon minimale dans le banc, pas une installation de Fluent Forms. Les commentaires et commandes sont de vrais objets WP/Woo sur une vraie MariaDB, classique et HPOS. Les suites n'utilisent que les archives commerciales fictives/locales déjà autorisées du banc ; aucun compte, archive ou site réel.

La page historique de documentation CRUD `https://developer.woocommerce.com/docs/extensions/core-concepts/crud/` a renvoyé une page absente ; elle n'est pas employée comme preuve. La référence de code officielle ci-dessus et la qualification du code installé sont la source retenue.
