# Fusion A-28 — Les messages de formulaires ne survivent pas à l'import

Fusionneur : Claude. Rapports croisés : `relectures/A-28/claude.md` (verdict *Conforme*) et `relectures/A-28/codex.md` (verdict *À corriger*). Brief : `briefs/A-28-messages-de-formulaires-et-import.md`. Cahier des charges : §4.4. Doctrine : §3.

Là où les deux rapports divergent, j'ai tranché en relisant le code (`wp/outils/staging/lib.php`, `form-policy.json`, `production/A-28/standard.md`) et le brief. Verdict fusionné : **À corriger** (voir fin).

## 1. Points retenus par les deux relecteurs

Les deux relectures concordent sur l'essentiel, et je confirme après relecture :

- **Standard d'abord, liste fermée sourcée.** `form-policy.json` énumère six suffixes Fluent Forms et deux types Flamingo ; aucun motif générique « form ». Les points 1 à 8 de `standard.md` portent une citation officielle avec adresse. CF7 seul n'a pas de stockage ; `wpcf7_contact_form` (définition) est conservé.
- **Une seule source partagée.** La même `form-policy.json` est lue côté PHP (`lib.php:55`) et Python (`table_policy.py`), transportée dans le vrai payload d'import.
- **Purge nominale correcte.** Tables de la liste vidées sans décision ; posts des types de la liste + révisions transitives + leurs `postmeta` supprimés (`lib.php:384-388`, `formPostIds()`). Vérifié à la main par les deux relecteurs (Cas A et B de Claude, « Message Flamingo » de Codex).
- **Refus `garder`/`anonymiser` sur table de la liste.** Côté PHP `FormDecisionRefused` (exit 78), côté Python `sql_preflight / FORM_MESSAGES_DECISION_REFUSED`, avant toute mutation. Étape + code + suffixe de table ; aucune valeur rendue.
- **Refus sans amorcer WordPress.** `verifier()` relit à neuf, et quand `issues` n'est pas vide la sonde n'est pas lancée (`SONDE_NON_EXECUTEE_DONNEES_REFUSEES`).
- **Type de contenu inconnu laissé ouvert.** `fiction_magazine` conservé et seulement signalé (`TYPES_CONTENU_INCONNUS_CONSERVES`) ; aucune décision prise, question posée dans les notes.
- **Sécurité/données.** Archives fictives, `@example.org`, aucun secret ; les refus n'exposent qu'un suffixe de la politique, jamais de texte ; le compteur ne sort qu'un entier. Le paywall (§4.4) n'est pas touché.
- **Doctrine §5.** `strict_types`, namespace `Imagine\Staging`, préfixe `imagine_`, codes constants. Pas de nouvelle extension ni de commande de Ced modifiée.
- **`PRET` ≠ GO.** Les deux rapports rappellent que la séparation entre `PRET` technique et autorisation d'accès au réel est bien tenue.

## 2. Points vus par un seul relecteur — avis du fusionneur

### 2.1 I1 (Codex) — le compteur de résidus ne compte jamais les `postmeta`. **Retenu, important.**

`lib.php:663` initialise `$formResidues` avec `count(formPostIds())` puis ajoute (`:668-669`) les lignes des six tables de la liste. **Jamais les lignes de `postmeta`.** Or Flamingo range les champs du visiteur (nom, message, situation) dans `postmeta` — `standard.md:5` le dit lui-même (« `update_post_meta` rangent sujet, champs et métadonnées dans posts/postmeta »).

Conséquence, relue dans le code : si le parent d'un message connu disparaît mais qu'une ligne `postmeta` de ce message survit, `formPostIds()` ne retrouve plus ce parent → le compteur vaut 0 → `verifier()` conclut `ok`. Et les scanners génériques (`lib.php:690-760`) ne rattrapent pas ce texte : un `meta_key` comme `_a28_message` n'est ni `sensitiveKey` ni `piiKey` ; un e-mail résiduel dans un `postmeta` de formulaire n'est `emailScope` que pour les posts de commande, donc il ne produit qu'un **avertissement** `EMAIL_HORS_PERIMETRE_COMPTES_COMMANDES`, pas une `issue` bloquante ; un nom ou un message en clair sans e-mail ne déclenche rien. Le texte du visiteur passe entièrement.

Le brief exige que l'étape de vérification « compte ce qui reste dans ces rangements et refuse s'il en reste ». Les `postmeta` sont le rangement principal du texte Flamingo ; le filet a donc un trou exactement là où vit le message. C'est le filet de sécurité demandé par le brief, pas un cas hors périmètre.

**Claude a vu le même mécanisme** (son point 3) mais l'a classé « limite, pas un défaut », en le réduisant à un `postmeta` **orphelin** d'un parent jamais présent. Le cadrage de Codex est plus juste et plus fort : il s'agit d'un message **connu** (type de la liste) dont le parent a été purgé — donc dans le périmètre annoncé. Conformément à la doctrine (CLAUDE.md), je l'écris clairement : **sur ce point Codex a vu ce que j'avais sous-pondéré.** Je remonte le classement de « limite » à **important**.

Ce n'est pas bloquant : la purge nominale supprime bien parent + `postmeta` ensemble, et aucune fuite réelle n'apparaît dans les preuves livrées. Mais la correction est due avant clôture, car c'est le contrôle de dernier recours du brief.

### 2.2 M1 (Codex) — deux tables sans citation officielle. **Retenu, mineur.**

`standard.md:11` (point 9) couvre `fluentform_draft_submissions` et `ff_scheduled_actions` par « Schéma développeur officiel », **sans adresse ni phrase citée** entre « » — contrairement aux points 3 à 8. Le brief demande « d'après leur documentation officielle, phrase citée » ; la grille §6 impose « sans source : doute ». Les empreintes d'`official-sources.json` ne remplacent pas l'extrait. **Doute** sur la justification de ces deux tables, sans conclure que les noms soient faux. Claude les avait jugées « défendables » sans vérifier le format de citation ; sur ce point aussi Codex est plus rigoureux.

### 2.3 Point Claude 1 (mineur) — `file_get_contents` dans le constructeur d'exception. **Retenu, mineur, décision technique.**

`lib.php:28` : `FormDecisionRefused` relit `form-policy.json` dans le constructeur d'une exception, sans garde d'E/S. Déterministe ici (fichier déjà lu par `Engine`), mais une erreur d'E/S à cet instant masquerait le refus d'origine. Codex ne l'a pas relevé ; je le conserve. Simplification : passer la liste déjà chargée.

### 2.4 Point Claude 2 (mineur) — code de refus sur table de la liste absente de l'archive. **Retenu, mineur, décision technique.**

`lib.php:85` : le refus `garder`/`anonymiser` exige `isset($inventory[$table])`. Une décision posée sur une table de la liste **absente** de l'archive retombe en `DECISION_INVALIDE` (code A-01 générique) au lieu de `FORM_MESSAGES_DECISION_REFUSED`. Aucun risque de donnée (rien à conserver), mais le code diffère. Codex ne l'a pas relevé ; je le conserve.

## 3. Désaccords

- **Verdict.** Claude : *Conforme*. Codex : *À corriger*. **Je tranche pour *À corriger*** : I1 est un trou réel dans le filet de vérification que le brief exige, et M1 est un manque de citation réel. Le reste du lot est conforme ; ce n'est ni un *À refaire* ni un *Conforme*.
- **Classement d'I1.** « Limite, pas un défaut » (Claude) contre « important » (Codex). **Je tranche pour *important*** (voir 2.1).
- **Divergence de vérification (pas un désaccord de fond).** Claude a pu rejouer la commande autorisée `rejouer.ps1` en conteneur jetable : `1151 tests, 36062 assertions, 0 échec — PASS`, outil `a28` 62 contrôles verts. Codex n'a **pas** pu lancer Docker (`Wsl/Service/E_ACCESSDENIED`) et ses exécutions Python natives butent sur des `PermissionError` d'environnement ; il s'est appuyé sur l'intégrité du paquet de preuves. **Aucun des deux n'a rejoué indépendamment la matrice native** (`verify.py`/`matrix.py` écrivent sous `production/`, hors droits du relecteur). Le rejeu global vert n'est donc attesté que par la course de Claude et par les JSON gelés. À garder en tête pour la clôture : I1 n'est démontré que par analyse statique, cohérente des deux côtés, et n'a pas été exécuté en PHP.

## 4. Instructions pour Hermès (numérotées)

1. **(important — I1)** Faire compter par `verifier()` les `postmeta` des messages de la liste qui survivent à la disparition de leur parent. Conserver jusqu'à la vérification une provenance fiable des identifiants de messages/révisions supprimés (ou une garantie équivalente), compter ces résidus de `postmeta` et refuser avec le code fermé existant (`FORM_MESSAGES_REMAIN`). **Ne pas** étendre à une suppression générale des `postmeta` ou des types inconnus.
2. **(important — I1, preuve)** Ajouter au banc un témoin de mutation où **seule** la purge des `postmeta` est omise (parent connu supprimé, `postmeta` `_a28_message` à texte canari conservé) et vérifier que `verifier()` **refuse** cette copie. C'est le témoin « contrôle retiré » que le brief réclame pour ce vecteur, aujourd'hui absent.
3. **(mineur — M1)** Dans `standard.md:11`, ajouter pour `fluentform_draft_submissions` et `ff_scheduled_actions` l'adresse officielle et la phrase citée exacte qui établissent leur stockage, en gardant la liste courte. À défaut de source, marquer « doute » explicitement.
4. **(mineur — décision technique)** `lib.php:28` : passer à `FormDecisionRefused` la liste déjà chargée au lieu de relire le fichier dans le constructeur d'exception. Défaut : comportement actuel conservé si non traité ; j'arbitre après coup.
5. **(mineur — décision technique)** `lib.php:85` : refuser tôt toute décision dont le suffixe ∈ liste, présente ou non dans l'archive, pour rendre `FORM_MESSAGES_DECISION_REFUSED` au lieu de `DECISION_INVALIDE`. Défaut : comportement actuel conservé si non traité ; j'arbitre après coup.

## 5. À arbitrer par Ced (touche au réel)

**Faut-il que l'import supprime aussi les types de contenu hors liste fermée ? oui / non.**
Aujourd'hui A-28 ne décide rien : un type inconnu (`fiction_magazine` dans le banc) est conservé et seulement signalé. Le risque de trancher « supprimer » est la perte de contenus du magazine rangés sous un type inattendu. **Défaut prudent proposé : non — conserver + signaler** (comportement actuel). Aucune anonymisation universelle des messages (pièces jointes, taxonomies libres, autres extensions) n'est prouvée : ce `PRET` ne devient pas un GO sur le réel.

## Verdict fusionné

**À corriger.**

- **Bloquant :** aucun.
- **Important :** I1 — la vérification ne compte pas les `postmeta` résiduels d'un message connu dont le parent a été purgé ; le filet laisse passer le texte du visiteur. Corrections 1 et 2.
- **Mineurs :** M1 (deux tables sans citation, correction 3) ; `file_get_contents` en constructeur d'exception (correction 4) ; code de refus sur table de la liste absente (correction 5).

Le lot fait l'essentiel de ce que le brief demande — liste fermée sourcée, purge nominale par la politique, refus avec étape/code/table sans valeur, type inconnu laissé ouvert — mais le contrôle de vérification exigé par le brief a un trou sur le rangement `postmeta` où vit le texte Flamingo, et deux tables manquent leur citation. À corriger avant clôture.

**Rappel (doctrine §6) : un verdict n'est pas un GO.** « À corriger » n'autorise aucun accès au réel. Même une fois I1 et M1 traités, la clôture reste soumise au second tour « prêt pour la validation » ; aucune anonymisation universelle n'est prouvée et aucune commande de Ced ne doit changer.
