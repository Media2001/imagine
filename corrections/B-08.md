## 2. Points vus par un seul relecteur, avec avis du fusionneur

### Vus par Codex seul — confirmés, importants

- **B08-01 — important — `Sujet.php:53-67` : une proposition contenant un antislash est refusée et perdue.**
  Avis : **Codex a raison, Claude l'a manqué.** Vérifié au code. `traiter()` déséchappe les champs une fois (`wp_unslash`, correct car `$_POST` est slashé). `enregistrer()` range ces valeurs propres dans `meta_input`, puis `wp_insert_post()` les écrit via l'API native des métadonnées, qui **déséchappe une seconde fois** (`update_metadata` appelle `wp_unslash` sur chaque valeur). Un sujet contenant littéralement `C:\dossier` est donc stocké « C:dossier » : l'antislash est détruit à l'écriture, la boucle de vérification `get_post_meta(...) !== $value` échoue, et la proposition est **supprimée avec un message de refus**. Double défaut : corruption de la donnée *et* refus d'une saisie légitime.
  Le test ne l'attrape pas : le stub `SujetWPStubs.php:56` copie `meta_input` tel quel dans `b08_meta` et ne reproduit pas le second `wp_unslash` du vrai WordPress — il **masque** le bug. Codex l'a aussi signalé.

- **B08-02 — important — `b08-seed.php:35-40, 90` : une création de menu interrompue ne peut pas être reprise.**
  Avis : **Codex a raison.** Vérifié au code. L'identité du menu n'est inscrite que par `update_option('imagine_b08_menu', …)` à la toute fin (ligne 90). Le terme de menu, lui, est persisté dès `wp_create_nav_menu` (ligne 40). Si le script échoue entre les deux (un item refusé ligne 65, un fatal, un timeout), le rejeu retrouve le menu (ligne 36) mais `$prior['menu']` vaut 0 → la garde ligne 37-38 lève `Collision menu B08` à chaque passage. Reprise impossible sans suppression manuelle de l'orphelin.
  Nuance du fusionneur : les **pages** sont, elles, récupérables individuellement (témoin `imagine_b08_page` écrit atomiquement avec la page, ligne 22) — l'éloge d'idempotence de Claude vaut pour les pages, pas pour le terme de menu, qui n'a aucun témoin propre et dépend d'une option écrite en dernier. Le point est circonscrit à l'outil de démo (`wp/outils/demo/`), mais la doctrine exige des seeds re-jouables (précédent B-06) et l'échec est un blocage dur : **important** retenu.

### Vus par Claude seul — mineurs, confirmés

- **`b08-seed.php:47` — URL vide si la page cible n'existe pas (mineur).** `get_permalink(get_page_by_path('nos-newsletters'))` renvoie `false` si la page est absente. Le brief ne liste pas les newsletters dans les dépendances (B-00, B-01, B-05, B-06) — **vérifié dans le brief**. L'item « Nos newsletters » reçoit alors une URL vide. Avis : réel, mineur ; le même risque existe pour `imagine_numero`, `imagine_evenement` et `wc_get_page_permalink('myaccount')`. Garde ou repli explicite souhaitable, non bloquant sur le site de démo où ces cibles existent.

- **`Soutenir.php:21-23` — schéma `http` accepté pour le lien de parts (mineur, décision technique).** `url()` autorise `https` **et** `http`. Pour un lien sortant vers CoopHub, `https` seul est plus prudent. La règle B-05 ne tranche pas le schéma. Avis : défaut technique, voir §4.

- **`Sujet.php:57` — titre d'admin uniforme (mineur, optionnel).** Toutes les propositions portent « Proposition de sujet » ; elles ne se distinguent que par la date. Pur confort de tri, aucune incidence métier ni fuite. Avis : optionnel, à laisser si le temps manque.

## 3. Désaccords

Un seul, sur le **verdict** et sur l'existence de points importants.

- Claude conclut **« Conforme, aucun point important »**. Codex conclut **« À corriger »** avec deux importants (B08-01, B08-02).
- **Tranché en faveur de Codex.** Les deux bugs sont confirmés par relecture du code (voir §2) : refus/corruption d'une saisie légitime contenant un antislash, et seed de menu non reprenable après interruption. Le verdict fusionné est donc **À corriger**. ## 4. Instructions pour Hermès (numérotées)

1. **Corriger B08-01 (antislash).** Écrire les métadonnées à la frontière d'écriture selon la convention WordPress : `wp_insert_post()` attend des données **slashées**. Appliquer `wp_slash()` aux valeurs de `meta_input` (ou, de façon équivalente, ne pas déséchapper trop tôt), tout en conservant les valeurs **normalisées** pour la boucle de vérification. Objectif : un sujet contenant `\` est accepté et relu à l'identique dans le détail admin et dans l'export C-21.
2. **Corriger le test qui masque B08-01.** Rendre le stub `SujetWPStubs.php` fidèle : `wp_insert_post` doit déséchapper `meta_input` comme le vrai `update_metadata`. Ajouter un cas passant par `$_POST` avec un sujet contenant un antislash, vérifiant le **succès** puis la **conservation exacte** du texte (détail admin + export).
3. **Corriger B08-02 (reprise du seed de menu).** Rendre la création du menu reprenable : inscrire un témoin durable d'appartenance au lot au moment de la création du terme (comme le témoin `imagine_b08_page` des pages), ou écrire l'option `imagine_b08_menu` par étapes, de sorte qu'un rejeu après interruption réutilise le menu et ses items sans doublon ni `Collision menu B08`. Conserver le refus d'un menu/item **étranger**. Tester : échec au milieu de la boucle d'items, puis rejeu complet sans intervention manuelle.
4. **Documenter B-08 dans le README** (`wp/plugins/imagine-site/README.md`) : les deux réglages, le stockage privé `imagine_sujet`, les callbacks export/effacement, la commande de rejeu des tests, renvoi vers `production/B-08/NOTE.md`. Combler aussi B-06 et B-07 si c'est au même coût.
5. **Durcir `b08-seed.php:47`** (et entrées de même nature) : ne poser l'URL que si la cible existe, sinon repli explicite, comme pour les entrées custom.
6. **Appliquer le défaut technique sur le schéma de parts** : restreindre `Soutenir::url()` à `https` (voir §5 « décision technique »).
7. *(Optionnel)* **`Sujet.php:57`** : colonne de liste admin date / sujet tronqué non sensible, si le temps le permet.
