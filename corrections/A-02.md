## 2. Points vus par un seul, avec avis du fusionneur

### Vus par Codex seul — **retenus comme importants** (Claude les avait manqués)

**C1 — Passerelles à héritage indirect omises.** `audit:299`.
Avis fusion : **confirmé, important.** Le regex n'accepte que `class X extends WC_Payment_Gateway(_CC|_eCheck)?`. Une passerelle concrète qui étend une classe de base intermédiaire (`A02_Gateway extends A02_Base`, `A02_Base extends WC_Payment_Gateway`) n'est pas reconnue : le fichier de base n'a pas de `$this->id`, et le fichier concret est de surcroît écarté par le préfiltre `str_contains('WC_Payment_Gateway')` ligne 363 s'il ne cite pas la classe mère. L'identifiant est pourtant statiquement résoluble. L'étiquette `dynamic_ids_unknown` (audit:372) couvre les IDs dynamiques, **pas** cette omission statique. L'inventaire des moyens de paiement (brief §2) devient incomplet sur un site réel.

**C2 — Comptage des abonnements gonflé par les doublons de métadonnées.** `audit:320` (HPOS) et `audit:323` (classique).
Avis fusion : **confirmé, important.** Les deux `LEFT JOIN` sur `_billing_period` / `_billing_interval` suivis de `COUNT(*)` multiplient les lignes dès qu'une clé de métadonnée est dupliquée pour un même abonnement ; des valeurs contradictoires peuvent même classer un abonnement dans plusieurs groupes. Codex l'a reproduit en SQL (SQLite en mémoire) : une métadonnée de période dupliquée fait passer le compte de 1 à 2 pour un seul abonnement. La fixture est propre, d'où le « ✔ » de Claude. Un audit d'existant doit précisément absorber ou signaler ce genre d'anomalie de données.

**C3 — Surcharge de thème parent masquée par l'enfant comptée comme risque actif.** `audit:537`.
Avis fusion : **confirmé, important.** Un thème est marqué `active` si `$name === $stylesheet || $name === $template` (audit:256) : dans un montage parent/enfant classique, **les deux** sont actifs. `risks()` parcourt alors leurs dossiers `woocommerce/` indépendamment sans résoudre la priorité (l'enfant l'emporte sur le parent). Si le parent porte une surcharge périmée et l'enfant la version à jour du même fichier, la copie périmée du parent — jamais servie — est quand même comptée dans la synthèse `outdated` (audit:601, priorité n°4). Le nombre de gabarits périmés « à traiter » surestime les fichiers réellement utilisés.

### Vus par Claude seul

- **`posts_by_year` en heure locale, non étiquetée** (mineur). `audit:437` : `YEAR(post_date)` (local), alors que `orders_by_year` est en UTC et porte l'étiquette `order_year_basis=UTC_creation` (audit:321/324/371). **Confirmé.** Près d'un 1ᵉʳ janvier un article peut basculer d'année selon le fuseau, et aucune base temporelle n'est déclarée pour les articles. Incohérence mineure à corriger ou au moins à étiqueter.
- **`custom_fields` = toutes les métadonnées** (mineur). `audit:424` : les 50 clés `postmeta` les plus fréquentes, dominées par des métas internes Woo/core. Interprétation littérale défendable (noms seulement, divulguée via `coverage`), mais liste bruitée pour qui cherche les vrais champs éditoriaux. Acceptable ; à documenter.

- **Tension d'emplacement `bascule/`** (mineur, sans gravité). Outil en lecture seule rangé sous un dossier décrit par la doctrine §4 comme « scripts numérotés qui transforment ». Le brief l'impose explicitement à `wp/outils/bascule/audit` : pas de contradiction, simple tension à connaître.

## 3. Désaccords

- **Verdict.** Claude : « Conforme », aucun important. Codex : « À corriger », trois importants. **Tranché en faveur de Codex** après revérification du code : les trois défauts sont réels. Le verdict fusionné est **À corriger**. La divergence tient à la méthode : Claude a déroulé la fixture (propre) ; Codex a construit les cas adverses et exécuté le SQL critique.
- **Tests rejoués.** Claude annonce `verify.py` **PASS** (122 assertions, conteneur absent confirmé). Codex obtient **code 1** : l'assertion de disponibilité Docker (`verify.py:74`) échoue sur `Wsl/Service/E_ACCESSDENIED`, les contrôles locaux passant tous avant cet arrêt. Les deux ont lu les mêmes reçus archivés ; aucun des deux n'a rejoué `run.py` (interdiction d'écriture). Avis fusion : l'écart n'est pas une contradiction sur le code mais sur l'environnement d'exécution (accès WSL/Docker du poste de relecture). Le **rejeu fonctionnel complet reste donc non confirmé** côté fusion ; les artefacts locaux, eux, sont cohérents. À reconfirmer dans une session dont l'environnement autorise Docker **et** l'écriture des preuves.

## 4. Instructions pour Hermès (numérotées)

1. **C1 — Passerelles.** Résoudre les héritages statiques des sources inventoriées avant de collecter les identifiants (sans instancier les classes) : suivre la chaîne `extends` à travers les fichiers d'une même extension jusqu'à `WC_Payment_Gateway`/`_CC`/`_eCheck`. Signaler explicitement les implémentations non résolues. Corriger aussi le préfiltre `commerce()` (audit:363) pour ne pas écarter un fichier concret qui ne cite pas littéralement `WC_Payment_Gateway`.
2. **C2 — Abonnements.** Ramener les métadonnées à une valeur déterministe par abonnement **avant** l'agrégation (sous-requête / `GROUP BY` sur l'ID avec sélection d'une seule ligne de meta), dans les deux branches (classique `audit:323` et HPOS `audit:320`). Signaler doublons et valeurs contradictoires au lieu de les transformer en abonnements. `COUNT(DISTINCT id)` seul ne suffit pas (il n'empêche pas le classement d'un abonnement dans plusieurs groupes contradictoires).

4. **`posts_by_year`.** Aligner la base temporelle sur celle des commandes (`post_date_gmt`, UTC) ou, à défaut, ajouter une étiquette de base explicite pour les articles, comme `order_year_basis` le fait pour le commerce (audit:437).
5. **Fixtures et preuves.** Ajouter au banc : (a) une passerelle à classe de base + classe concrète dans deux fichiers, plus une classe sans lien avec les passerelles ; (b) un abonnement avec métadonnées de période dupliquées (identiques puis contradictoires), dans les deux stockages ; (c) un thème enfant masquant une surcharge périmée du parent, et un parent dont la surcharge reste utilisée faute d'équivalent enfant. Puis **régénérer les preuves** sous `production/A-02/preuves/` dans une session autorisée à écrire, et relancer `verify.py` dans un environnement où Docker/WSL est accessible.
