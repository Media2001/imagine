## 1. Points retenus par les deux relecteurs

- **Conformité fonctionnelle du code** : normalisation (préfixe `BE` contigu,
  points/tirets/espaces `Zs`, ancien format neuf chiffres complété par un seul zéro),
  contrôle de cohérence (dix chiffres, premier chiffre 0/1, clé `97 − (8 premiers mod 97)`),
  motifs français, interface `RechercheDenomination` + implémentation vide sans réseau.
  Les deux relecteurs concluent : conforme au périmètre.
  `src/Entreprise/NumeroEntreprise.php:14-57`.
- **Exactitude métier** : déroulé manuel sur numéros calculés (base `01234567` → clé 49 ;
  neuf chiffres préfixés d'un zéro → clé préservée ; clé fausse `0123456700` → refus
  `CleIncorrecte`, `normalise`/`affichage()` nuls). Les deux concordent avec le code.
  **Aucun défaut métier identifié** par l'un ou l'autre.
- **Tests non relancés indépendamment** : droits/environnement refusés des deux côtés
  (Claude : `php`/`docker`/`composer` ; Codex : `runner-state.json` absent, conteneur
  nettoyé, pas de `vendor`). Les deux ont vérifié la **cohérence interne** des preuves
  Hermès (41 tests Entreprise, suite complète 169 tests / 19 860 assertions, sans échec).
  Les deux rappellent qu'il faut **rejouer la suite dans le runner jetable** avant toute
  suite. → voir Instruction 1.
- **Sécurité et données** : aucun secret, aucune donnée réelle, numéros calculés, pas de
  réseau, pas de journalisation de la saisie, résultat immuable, `normalise` null après
  refus. Rien à signaler pour les deux.
- **« Standard d'abord » différé** : les deux constatent que la vérification qu'une
  extension retenue couvre déjà cette normalisation n'est **pas documentée** et renvoyée
  à A-00 / l'intégration. Claude la juge « acceptable car signalée » ; Codex en fait un
  point mineur à corriger (C02-02). Les deux la voient. → Instruction 4.

## 2. Points vus par un seul relecteur (avis du fusionneur)

- **[Codex seul — C02-01] Annexe BCE/VIES : conditions d'accès et limites non établies.**
  `production/C-02/notes.md:57-79`. Les sources sont nommées avec adresses, mais les
  conditions/limites sont présentées comme questions « à confirmer », pas comme un
  livrable documentaire. **Avis : retenu, important.** Le brief demande explicitement
  « leurs conditions d'accès et leurs limites, avec les adresses de leur documentation ».
  Ces conditions se documentent depuis des pages officielles **sans aucun appel réseau
  ni consultation d'entreprise** — donc dans le périmètre. Lister ce qu'il faudra
  vérifier n'exécute pas cette exigence. C'est le point de bascule du verdict. → Instruction 2.
- **[Claude seul] Motif supplémentaire `PremierChiffre` hors liste du brief (item 3).**
  `Motif.php:13`, `NumeroEntreprise.php:35`. **Avis : retenu, mineur.** Le refus d'un
  premier chiffre 2 est **exigé par le brief item 2** (« premier chiffre 0 ou 1 ») :
  sans ce contrôle, `2234567825` passerait la clé. L'ajout est donc nécessaire et justifié.
  Seule la **granularité du motif** (motif distinct vs fondu dans un motif existant) est
  un choix de présentation. → À arbitrer par Ced, question 2.
- **[Claude seul] Format d'affichage non épinglé par une assertion littérale.**
  `NumeroEntrepriseTest.php:30,130`. **Avis : retenu, mineur.** Le test reconstruit
  l'attendu avec la même formule `substr()` que la production ; un changement concordant
  du regroupement `4.3.3` passerait inaperçu. → Instruction 3.
- **[Claude seul] `ResultatRecherche` conflue dénomination vide et mal encodée.**
  `src/Entreprise/ResultatRecherche.php:14` : un seul `preg_match` (retour `false` pour
  l'UTF-8 invalide, `1` pour le vide) → même message pour deux causes. **Avis : retenu,
  cosmétique.** Fonctionne ; sans impact tant que la recherche reste indisponible. → Instruction 5 (optionnelle).

## 3. Désaccords

- **Verdict global.** Claude : **Conforme**. Codex : **À corriger**.
  **Tranché : À corriger**, sur le seul motif de l'annexe documentaire (C02-01).
  Le code, les tests et la sécurité ne motivent aucune correction ; les deux relecteurs
  l'admettent. Le désaccord porte uniquement sur le statut du livrable `notes.md`.
- **Annexe BCE/VIES (C02-01).** Claude l'a classée « conforme » au titre de la grille §6
  (« pas de source → doute assumé »). **Je reviens sur mon rapport.** La grille §6 vise
  les lots d'étude où l'on ne peut citer de source ; ici le brief demande un livrable
  précis — conditions et limites, avec adresses — réalisable sans action interdite.
  « Doute » honnête ne vaut pas exécution du livrable. Codex a raison contre moi sur ce point.
