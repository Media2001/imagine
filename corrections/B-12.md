## 1. Points retenus par les deux relecteurs

- **Conception du verrou conforme au brief.** Quatre points d'accroche natifs, un par surface (`IntegrationsCorps.php:13-18`) : handler `wp_embed_register_handler` en `PHP_INT_MIN` (avant fournisseurs et avant le cache `_oembed_*`), `pre_oembed_result` pour la résolution directe, `pre_render_block` pour l'ancien HTML de bloc, `rest_dispatch_request` pour l'aperçu proxy. Les deux rapports valident ce choix.
- **Verrou inconditionnel, indépendant de B-11.** `IntegrationsCorps` ne lit jamais `Medias::OPTION` ; l'adresse externe devient un lien quel que soit le réglage B-11. Les deux rapports le confirment (OFF puis ON identiques).
- **Aucun réglage nouveau, aucune réécriture du corps.** Le code n'agit qu'au rendu/résolution, aucun `wp_update_post` ; levée future documentée sans s'appuyer sur B-11 comme preuve de consentement.
- **Exception interne correcte.** `externe()` ne classe « interne » que sur égalité stricte hôte + schéma + port + chemin sous la racine (`IntegrationsCorps.php:21-42`) ; le biais est vers « externe » (donc lien), côté sûr. Détournement d'auth (`user`/`pass`), préfixe voisin, sous-domaine piège : correctement traités. Convergence des deux rapports.
- **Sécurité des sorties et permissions.** Échappement `esc_url($url, ['http','https'])` + `esc_html($url)` ; l'aperçu re-vérifie `current_user_can('edit_posts')` et ne contourne aucune permission native. Aucun secret, aucune donnée réelle ; fixtures fictives. Paywall non touché. Les deux rapports concordent.
- **Doctrine « standard d'abord ».** Hooks natifs documentés, sept sources officielles dans `sources-officielles-V2.json`, `strict_types`, namespace `Imagine\Site`, préfixe `imagine_`, aucune extension tierce modifiée. Convergence.
- **Portée exclue explicite.** Les `<iframe>` collés à la main dans le corps restent hors scope — écrit dans le brief, `NOTE.md` et `A-VOIR.md`. Les deux rapports le relèvent sans en faire un défaut.
- **Limite de vérification partagée.** Aucun de nous deux n'a rejoué la matrice native dans un vrai WordPress. J'ai rejoué la suite scellée `rejouer.ps1` (conteneur, **1201 tests / 36613 assertions, PASS**, test du lot inclus : 5 tests / 37 assertions) ; Codex n'a pas pu l'atteindre (accès WSL refusé, `Wsl/Service/E_ACCESSDENIED`, 0 test PHP) et a lancé les outils démo Python. La garantie « zéro sortie » du pipeline réel repose sur la matrice native `b12-runtime.php`, hors de notre portée à tous les deux.

## 2. Points vus par un seul, avec l'avis du fusionneur

### Vus par Codex seul

- **B12-01 — bloquant — contournement du verrou par la casse de la route proxy (`IntegrationsCorps.php:72`).** `apercu()` compare `rtrim($request->get_route(), '/')` à la chaîne exacte `/oembed/1.0/proxy`. Or le routeur REST natif apparie les routes avec le drapeau insensible à la casse (`@^…$@i` dans `WP_REST_Server::match_request_to_handler()`) : une requête authentifiée et autorisée vers `/oembed/1.0/PROXY` est **dispatchée au callback natif du proxy**, mais le garde de B-12 échoue (la casse diffère) et renvoie `$response` inchangé. Le proxy natif poursuit alors vers `get_data()` (que `pre_oembed_result` n'intercepte pas) et, s'il existe un transient préexistant, peut restituer l'ancien HTML externe. **Avis : retenu, bloquant — Codex a raison, je l'avais manqué.** J'ai confirmé par relecture : le code s'appuie sur `$request->get_route()` (le chemin brut reçu) au lieu du 3ᵉ paramètre `$route` (la route canonique fournie par le dispatch). Le trou ne touche que l'aperçu éditeur et exige un utilisateur déjà `edit_posts` forgeant une variante de casse — il ne se déclenche jamais dans le flux Gutenberg ordinaire (toujours en minuscules) et, dans la démo, B-00 `imagine_demo_offline` bloquerait encore le transport. **Mais** le lot *est* le verrou « inconditionnel » du §3.14/§4.4 ; une voie connue qui laisse ressortir une résolution externe (ou un ancien iframe en cache, sans même de transport) contredit frontalement sa raison d'être. Bloquant confirmé.
- **B12-02 — important — réception adossée à un bootstrap périmé (`production/B-12/reception-V2.json:11`).** La réception certifie pour `imagine-site.php` l'empreinte `9530b508…`, alors que l'arbre actuel vaut `e27ee706…`. **Avis : retenu, important — confirmé par calcul direct.** J'ai relu : l'écart vient de l'ajout **C-29** (lignes 178-181, enregistrement de `ContactBrevo`), postérieur à la réception. Le branchement propre de B-12 (lignes 174-176) est **intact et inchangé** ; aucune modification du code B-12 n'est en cause. C'est bien l'explication du `b12-verifier.py` que Codex a vu **échouer** (`AssertionError: SOURCES`) : le vérificateur compare les empreintes de sources à la réception et bute sur `imagine-site.php` modifié par C-29. Reste que la réception livrée **échoue sur l'arbre à relire** et que le complément voisins (B-11/C-27/C-28) ne couvre pas l'ajout C-29 : on ne peut pas présenter la réception actuelle comme verte. Important confirmé.

### Vus par Claude seul

- **Dépendance à l'ordre interne non contractuel du cœur WP** (`IntegrationsCorps.php:16-18`, `NOTE.md`). Le dispositif suppose handlers avant fournisseurs et `rest_dispatch_request` après permissions mais avant le transient du proxy. Vrai en WP 7.0.9, non garanti par contrat public. **Avis : maintenu, mineur.** À inscrire comme condition de non-régression : rejouer la matrice native à chaque montée de version du cœur. (À noter : B12-01 est une illustration de cette fragilité d'appui sur le détail interne du routeur.)
- **Tests PHPUnit sur doublures maison, pas sur le vrai WP** (`IntegrationsCorpsB12Stubs.php`). La preuve « zéro sortie » n'est pas dans la suite scellée mais dans la matrice native hors conteneur. **Avis : maintenu, mineur** — à dire explicitement dans le README du lot.
- **Compteurs du worker périmés.** `NOTE.md`/`A-VOIR.md` annoncent « 1 200 tests / 36 610 assertions » ; le rejeu observé donne **1 201 / 36 613**, les deux verts. **Avis : maintenu, mineur** — aligner pour la traçabilité.
