## 1. Points retenus par les deux relecteurs

Accord sur le fond conforme, point par point :

- **Standard d'abord** : type natif `imagine_vente` privé + option non autoloadée `imagine_vente_actifs`, aucune table, aucune bibliothèque. Note de choix avec sources officielles. Conforme doctrine §4.
- **Page liste + recherche** : recherche par localité ou code postal, liste (nom, adresse, code postal, localité), tri localité puis nom. Conforme §3.14. Le code postal affiché en plus est un plus, pas un écart.
- **Chargement CSV + correspondance** : remplace la liste, annonce pris/refusés avec numéro de ligne physique et motif **sans recopier la donnée**, se rejoue sans doublon (doublon exact refusé dans un import ; rejeu identique qui conserve les IDs via le retour anticipé `PointsVente.php:93`). Conforme au brief.
- **Carte** : réglage fermé `carte=0|1`, défaut `0`, valeur inconnue ramenée à `0`. Allumée, simple bloc texte « Carte non raccordée », zéro script/image/iframe/tiers. Conforme §4.4. Trois lignes « carte ultérieure » présentes.
- **Aucun géocodage, aucun appel sortant** : vérifié par lecture, confirmé par les témoins navigateur archivés (zéro requête tierce, carte éteinte comme allumée).
- **Personne / téléphone masqués par défaut** : affichés seulement si la clé est dans la correspondance courante (`PointsVente.php:143`) ; retrait du mapping = masquage immédiat sans réimport. Conforme à la règle « un commerce, pas une personne » (brief) ; pas de raccord C-21.
- **Sécurité** : `manage_options` + nonce sur chaque POST ; CPT privé, `show_in_rest=false`, exclu de la recherche ; méta `imagine_vente_ligne` non exposée à REST ; échappement systématique en sortie ; CSV borné (2 Mio), UTF-8 vérifié, octets nuls refusés, non conservé. Pas de XSS ni de voie de fuite identifiée.
- **Données** : jeu entièrement fictif, déclaré dans `A-VOIR.md`. Aucun secret.
- **Conventions §5** : `strict_types`, namespace `Imagine\`, préfixe `imagine_`, logique pure séparée de l'adaptateur WP.

**Écart de severité sur deux points vus par les deux** (détaillé en §3 Désaccords, instructions en §4) :

- **I1 — normalisation des accents incomplète** (`PointsVenteRegles.php:18`). Vu par les deux ; Claude l'a classé mineur (angle `œ`/`æ`), Codex important (angle composition Unicode). **Je tranche : important.** Le brief exige explicitement une recherche « sans tenir compte des accents » et en fait un critère de preuve. Or `cle()` plie une table de précomposés puis retire les marques `\p{M}`, sans décomposer : un caractère précomposé absent de la table survit accentué, alors que sa forme décomposée est pliée. Même accent, deux clés selon la composition. Concret pour des données françaises réelles : `Œuf-en-Ternois` (commune réelle) reste `œ`, « oeuf » ne la trouve pas. Codex a vu l'asymétrie NFC/NFD que Claude avait manquée ; Claude a donné le cas concret `œ`/`æ` qui touche de vraies communes. Les deux se complètent.
- **I2 — nettoyage non repris après échec de remplacement** (`PointsVente.php:114-116`). Vu par les deux ; Claude mineur (« orphelins invisibles »), Codex important (rétention de données personnelles, jamais retentée au rejeu). **Je tranche : important** (trigger étroit). Après la bascule, si `wp_delete_post` échoue sur un ancien ID, `nettoyage_refuse` est levé mais la nouvelle liste est déjà active. Les anciens posts deviennent orphelins — avec leurs éventuelles méta personne/téléphone. Au rejeu du même CSV, `self::lignes() === $result['lignes']` est vrai, retour anticipé ligne 94 : le nettoyage n'est **jamais** retenté. Codex a vu ce « jamais retenté » que la version de Claude n'articulait pas. Pas de fuite (CPT privé, hors REST), donc non bloquant ; mais pour un projet dont la doctrine est « un commerce, pas une personne », laisser des données personnelles résiduelles après un remplacement censé les retirer est un vrai défaut d'hygiène.

## 2. Points vus par un seul relecteur, avis du fusionneur

**Vus par Codex seul :**

- **M1 — motifs de refus non traduits** (`PointsVente.php:205`). *Retenu, mineur.* Les codes techniques (`nombre_colonnes`, `champ_requis`, `syntaxe_csv`, `doublon`, `champ_invalide`) sont injectés tels quels dans l'interface d'admin. Seul « Ligne %1$d : %2$s » est traduisible. Contraire au §5 (texte d'UI français et traduisible). Claude l'a manqué. Fix : convertir les codes en libellés français traduisibles à l'affichage, en gardant les codes pour les tests, sans inclure les valeurs du CSV.

**Vus par Claude seul :**

- **C1 — récupération d'une liste corrompue** (`PointsVente.php:93`, via `lignes()` `:68`). *Retenu, mineur.* Le contrôle d'idempotence appelle `self::lignes()`, qui **lève** `RuntimeException('liste_illisible')` si un seul post actif est cassé (méta absente, type changé). L'import censé *remplacer* la liste corrompue est alors avorté : on ne peut plus réparer par un nouveau chargement. Trigger étroit. Codex ne l'a pas vu. Fix : `try/catch` autour de la comparaison pour poursuivre vers le remplacement complet si l'ancienne liste est illisible.
- **C2 — idempotence sensible à l'ordre des clés du mapping** (`PointsVente.php:93`). *Retenu, mineur.* Le `===` est sensible à l'ordre des clés (PHP compare les tableaux associatifs clé/valeur **dans l'ordre**). Réordonner le JSON de correspondance (mêmes clés) sur un CSV identique provoque un réinsert complet, nouveaux IDs, au lieu du no-op. Bénin. Fix : `ksort` avant comparaison, ou documenter la limite.
- **C3 — micro-perf d'affichage** (`PointsVente.php:143`). *Retenu, mineur.* `self::configuration()` (donc `get_option`) est rappelée pour chaque ligne et chaque clé facultative dans la boucle. Fix : lire la configuration une fois hors boucle.
- **C4 — écart de preuve chiffrée.** *Retenu, mineur/informatif.* `A-VOIR.md`/README citent 1 175 tests / 36 407 assertions ; le rejeu frais de Claude donne 1 176 / 36 417. Écart imputé au chantier B-11 en cours dans l'arbre (non suivi), pas à B-10. À aligner quand B-11 sera stable.
- **C5 — liaison page↔extension dans le seed de démo** (`wp/outils/demo/b10-seed.php`). *Retenu, prospectif, hors périmètre démo.* Pour la vraie mise en ligne, la création/association de la page devra devenir un script de bascule versionné (doctrine « rejouable »). Non exigé par ce lot de démo.

**Note de couverture de vérification (en faveur de la preuve) :** Claude a **rejoué** la suite PHP autorisée (conteneur jetable, hors réseau, dépôt en lecture seule) : 1 176 tests verts, dont les 6 de `PointsVenteReglesTest`. Codex n'a **pas pu** rejouer PHP (WSL `E_ACCESSDENIED`, pas de PHP au PATH) et s'est appuyé sur le vérificateur de sources et les preuves archivées. La preuve « tests verts » est donc confirmée par une ré-exécution indépendante, pas seulement par les logs d'Hermès. La couche WordPress (idempotence des IDs, masquage, rendu carte, zéro requête tierce) reste prouvée par les recettes d'Hermès, non rejouables sans accès au site, par les deux relecteurs.

## 4. Instructions pour Hermès (numérotées, par gravité)

1. **(I1, important)** Rendre la désaccentuation complète et cohérente dans `PointsVenteRegles::cle()`. Décomposer la chaîne avant de retirer `\p{M}` (par ex. `Normalizer::normalize($v, Normalizer::FORM_D)` si l'extension intl est présente — voir décision technique ci-dessous), **et** ajouter à la table les ligatures qui ne se décomposent pas : `œ→oe`, `æ→ae`. Ajouter un test comparant, pour un caractère **absent de la table**, les formes précomposée, décomposée et désaccentuée, plus un cas `œ`/`oe`.
2. **(I2, important)** Rendre le nettoyage de l'ancienne liste repris et non destructeur de l'invariant. Après la bascule, conserver explicitement les IDs restant à nettoyer dans un état de reprise ; retenter ce nettoyage même lors d'un rejeu identique (ne pas court-circuiter par le retour anticipé ligne 94 tant qu'il reste des orphelins) ; distinguer « liste remplacée, nettoyage incomplet » d'un import refusé. Ajouter un test : échec de suppression d'un ancien post, puis rejeu identique qui reprend le nettoyage.
3. **(M1, mineur)** Convertir les motifs de refus en libellés français traduisibles à l'affichage (`PointsVente.php:205`), en gardant les codes bruts pour les tests, sans jamais inclure les valeurs du CSV.
4. **(C1, mineur)** Encadrer le contrôle d'idempotence `self::lignes() === …` (`PointsVente.php:93`) d'un `try/catch` : si l'ancienne liste est illisible, poursuivre vers le remplacement complet au lieu d'abandonner.
5. **(C3, mineur)** Lire `self::configuration()` une seule fois hors de la boucle d'affichage (`PointsVente.php:143`).
6. **(C2, mineur)** Au choix : normaliser l'ordre des clés (`ksort`) avant le `===` d'idempotence pour rendre l'ordre du mapping indifférent, sinon documenter la limite dans `NOTE.md`.
7. **(C4, mineur)** Aligner les chiffres de preuve (1 175→1 176 / 36 407→36 417) une fois B-11 stabilisé, et re-geler la régression.
8. **(C5, prospectif)** Noter que la liaison page↔extension devra passer du seed de démo à un script de bascule versionné pour la vraie mise en ligne. Hors périmètre de ce lot.
