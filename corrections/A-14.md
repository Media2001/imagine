Déroulé manuel concordant des deux côtés (30 lignes = 4 rapprochées + 23 sans compte + 2 invalides + 1 ambiguë ; 7 comptes sans contact ; 1 injoignable). ## 1. Points retenus par les deux relecteurs

- **Mineur — libellés anglais dans `resume.md`** (`command.php:78-79`). Le résumé lisible recopie les clés machine (`contacts_total`, `accounts_without_contact`, …). Contraire à la doctrine §5 (textes d'interface en français). Les deux relecteurs le signalent, même ligne, même correction. Confirmé en relisant le code : la boucle `foreach ($result['counts'] as $name => $count)` imprime la clé brute. `resume.json` n'est pas concerné.

## 2. Points vus par un seul, avec l'avis du fusionneur

- **Codex seul — Mineur — justification « standard d'abord » du SQL de collecte** (`Accounts.php:22-30`). La détection de l'abonnement actif est reconstruite en SQL (classic : `posts`/`postmeta` ; HPOS : `wc_orders`), sans dire pourquoi l'API native de WooCommerce Subscriptions n'est pas utilisée (doctrine §4, grille §5).
  **Avis du fusionneur : fondé, Codex a raison contre Claude qui l'a manqué.** J'ai vérifié : `a11/Runtime.php:117` exécute `require ABSPATH . 'wp-settings.php'`, qui charge WordPress **et les extensions actives**. Les fonctions `wcs_*` (p. ex. `wcs_get_subscriptions`) étaient donc disponibles : le SQL direct est un **choix**, pas une nécessité technique. Le README documente le *quoi* (abonnement actif = état natif `active`) mais jamais le *pourquoi* du SQL. Point mineur, de documentation : la stratégie SQL est défendable (déterministe, auditable, compatible avec la base clôturée en lecture seule) et ne doit **pas** être changée sans nécessité démontrée ; il manque seulement sa justification écrite.

- **Claude seul — suite PHP autorisée (T01) rouge.** `TableauBordReglesTest::testCatalogueIsMemoizedWithinRequest` échoue (1 échec sur 1087 tests). Codex ne l'a pas vu : il n'a lancé que `verify.py` d'A-14, pas la suite globale.
  **Avis du fusionneur : réel, mais hors périmètre A-14.** L'échec vient de l'extension `imagine-site` (tableau de bord natif, fichiers non committés), aucune occurrence `a14`/`Contacts`/`Matcher` dans la sortie. N'empêche pas la clôture d'A-14, mais **bloque toute clôture globale** tant qu'il n'est pas corrigé dans son propre lot. À tracer.

- **Claude seul — double comptage des lignes dupliquées dans `contacts_with_account`** (`Matcher.php:53-57,81`). Les lignes 2 et 3 (même email) comptent toutes deux dans « avec compte » (4 lignes pour 3 comptes distincts).
  **Avis du fusionneur : ce n'est pas un défaut.** Le comptage est **par ligne source**, documenté au README l.13 et réconciliable via `duplicate_contact_lines`. Codex a vu le même mécanisme et l'a jugé conforme (« doublons comptés par lignes concernées »). On garde le comptage par ligne ; seul un rappel de lecture est utile (point 4).

- **Codex seul — couverture incomplète de branches documentées.** Codex note que `pending-cancel`, le domaine technique réservé sans marqueur `imagine_sans_email`, et « plusieurs abonnements sur un même compte » ne sont pas tous prouvés par un test dédié.
  **Avis du fusionneur : recevable, mineur.** Ces branches existent dans le code (`Accounts.php:21-44`) et sont documentées (README l.15), mais la grille §3 demande que le test vérifie la règle, pas qu'il la suppose. À compléter (point 3).
