## 2. Points vus par un seul relecteur

### Vus par Codex seul

- **M1 — Preuve de réutilisation du cache insuffisante — `wp/tests/demo/b15-runtime.php:22`.**
  `numero_cache_reutilise` n'assure que `PiedPage::numero() === $initial`. Or `Accueil::numero()` est déterministe : une reconstruction intégrale à chaque appel produirait le **même** HTML et passerait l'assertion. Le test prouve le déterminisme, pas la mise en cache.
  **Avis du fusionneur : retenu, confirmé par le code.** Le retour anticipé existe bien (`PiedPage.php:52-55`), mais un mutant qui le supprimerait survivrait à la ligne 22. Le brief (ligne 24) exige explicitement « construite une fois et gardée en cache » : l'exigence est **tenue dans le code mais sous-prouvée**. Codex a vu juste ; Claude a fait confiance en bloc au script runtime et a manqué ce trou précis. → Instruction 1.

- **Limite de réexécution PHP côté Codex.** Codex n'a pas pu rejouer PHP (absent du PATH ; conteneur refusé par WSL) ; il s'appuie sur `verifier.py` / `qualifier.py` (résultats archivés). **Avis : noté comme limite de preuve, non comme défaut.** Comblé par Claude (ci-dessous).

### Vus par Claude seul

- **Rejeu PHP frais réellement exécuté.** Claude a relancé la suite autorisée (`rejouer.ps1`, conteneur jetable `network=none`) : `REJEU : 1209 tests, 36693 assertions, 0 échecs — PASS`. C'est la preuve d'exécution la plus forte des deux rapports ; elle lève la réserve de Codex.
- **Point mineur — Invalidation de cache trop large — `PiedPage.php:16`.** Le transient est purgé par `save_post_attachment`, `deleted_post`, `added_post_meta`, `updated_post_meta`, `deleted_post_meta` pour tout le site : toute métadonnée ou tout attachement renouvelle inutilement le pied. **Avis : retenu, mineur.** Sûr mais coûteux. → Instruction 2.
- **Point mineur — Résolution d'URL hétérogène — `PiedPage.php:86,91`.** `abonnement` passe par `get_page_by_path` ; `newsletter` et `point-vente` émettent des slugs en dur (`/nos-newsletters/`, `/points-de-vente/`) sans vérifier la cible. **Avis : retenu, mineur.** Conforme au brief (« un lien suffit ») et aligné sur `Accueil.php` pour la newsletter ; lien mort seulement si un slug change. → Instruction 3.
- **Point mineur — Comptage non rafraîchi dans `A-VOIR.md`.** Annonce « 1208 tests / 36685 assertions » ; le rejeu frais donne 1209 / 36693 (écart expliqué par un garde-fou B-14 postérieur). Décalage de rédaction, pas un défaut de code. **Avis : retenu, mineur.** → Instruction 4.

## 3. Désaccords

- **Verdict : « Conforme » (Claude) contre « À corriger » (Codex).**
  **Tranché en faveur de Codex : À corriger.** Motif : le brief exige noir sur blanc que la zone du numéro soit « construite une fois et gardée en cache » (ligne 24) ; la seule assertion qui couvre cette réutilisation (`b15-runtime.php:22`) ne la prouve pas, et le test PHPUnit relevé par Claude est de son côté tautologique. Il reste donc une correction concrète à faire sur la preuve avant de clore. Un rapport « Conforme — mineurs seulement » est ici moins cohérent avec la grille (un point à corriger subsiste) que « À corriger ». Aucune divergence sur le fond du code : les deux s'accordent sur aucun bloquant, aucun important.

**Verdict de fusion : À corriger** — renforcement de la preuve de cache, plus trois mineurs. Aucun bloquant, aucun important.
