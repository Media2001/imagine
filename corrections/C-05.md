## 1. Points retenus par les deux relecteurs

Ce n'est pas une invention : c'est l'arbitrage de Ced du 22/11 (`decisions.md`, `arbitrages-2026-11-22.md` §C-05), qui corrige la formulation du brief. Hermès a suivi la décision **et** l'a signalé (`proposition.md` §1). Doctrine §1 : la décision l'emporte sur le texte du brief. → Conforme.
- **Livrables présents.** Moteur PHP pur déléguant numéros et dates à C-01 ; comparaison de deux voies Subscriptions avec recommandation motivée ; adaptation manuelle ; preuves archivées sur plusieurs blocs ; réglages ouverts (marge, après-rejet, tarif) conformes à l'arbitrage.
- **Preuves liées au code relu.** Les deux relecteurs ont recalculé indépendamment les SHA-256 des 16 fichiers des manifests (`reprise-final-unit.json`, `reprise-final-e2e.json`) → **0 écart, 0 manquant**. Les reçus correspondent exactement au code relu : 380 tests / 2 289 assertions / 0 échec ; e2e `exit_code` 0.
- **Aucun test rejoué localement, par aucun des deux.** PHP/Docker absents du PATH ; le runner passe par `wsl.exe` (refusé en session) et écrit dans `production/C-05/preuves/` (surface interdite en écriture au relecteur). Les deux le disent, comme le prévoit la grille. → Un rejeu dans l'environnement de test autorisé reste nécessaire après correction.
- **Sécurité et données : rien à signaler.** Aucun secret, aucune donnée réelle (`@example.org`, identités fictives). `RaccordManuel` : triple garde (drapeau manuel + passerelle vide + méta `imagine_c05_fixture`). `ReglagesAdministration` : Settings API, nonce, capacité `manage_woocommerce`, sorties échappées, `show_in_rest => false`, saisie invalide → option précédente conservée. Plugin **non branché** (aucun amorçage, zéro référence hors dossier). Paywall non concerné.
- **Doctrine respectée.** Standard examiné avant le sur-mesure ; logique métier hors WordPress, testable sans base ; types stricts, namespace `Imagine\`, préfixe `imagine_`, libellés traduisibles ; chaque réglage ouvert testé dans ses positions.
- **Parcours complets non exercés.** Mandat SEPA, emails (R-17), opposition à reconduction, transmission Odoo : hors du périmètre technique de cette proposition. Acceptable pour un prototype ; à valider au branchement.

## 2. Points vus par un seul relecteur, avec l'avis du fusionneur

- **C05-01 (Codex, important) — RETENU. Codex avait raison, Claude l'a manqué.**
  `Planificateur::planifier()` est appelé **par bloc** (`Moteur::numeros()` renvoie quatre numéros pour une `Annee`), et `src/Echeancier/Planificateur.php:36` remet `$precedente = null` à chaque appel. Le contrôle `DATES_NON_CROISSANTES` ne compare donc jamais la première échéance reconduite à la dernière du bloc précédent : la garantie ne tient qu'**à l'intérieur** d'un bloc.
  Vérifié dans le code : `src/Numeros/Calendrier.php:59` ne rejette que les clôtures **strictement** inversées (`$numero->cloture < $precedent->cloture`) ; l'**égalité** entre deux clôtures régulières est acceptée. Le contre-exemple de Codex est donc atteignable : en donnant à `REG-2028-04` la même clôture que `REG-2028-01`, pour une commande du 20/02/2027 marge 7, le rang 4 initial et le rang 1 reconduit tombent tous deux au même instant (03/01/2028 00:00 Bruxelles). Chaque bloc est croissant pris isolément ; les deux appels réussissent ; le raccord reçoit deux positions successives au même instant.
  Cela contredit l'affirmation de Claude (son point « Bornes de clôture : dates strictement croissantes ✓ »), vraie seulement intra-bloc. → Important, à corriger.

- **I1 (Claude, important) — RETENU.** `wp/plugins/imagine-pilotage/phpunit.xml` ne déclare que les testsuites `Numeros/Robots/Entreprise/Acces/Envoi` : **aucune** testsuite `Echeancier`. `tests/Echeancier/run.php` est un banc maison autonome, pas une classe PHPUnit. Conséquence : la commande de test du brief (`composer test` → `phpunit`) n'exécute **rien** du lot et ressort au vert à tort. Codex a vu le banc autonome mais ne l'a pas classé en défaut ; le fusionneur retient le point comme important (risque de fausse confiance en CI, alors que tous les lots voisins sont en PHPUnit).

- **M1 (Claude, mineur) — RETENU.** `Planificateur::planifier(Annee $annee, DateTimeImmutable $finEngagement, …)` : le 2ᵉ paramètre ne sert plus qu'à une garde `≤ début` (`Planificateur.php:28`) et ne borne plus les paiements (« compatibilité positionnelle »). Il est typé **non-nullable** alors que la source prévue `Annee::finNumerique()` renvoie `?DateTimeImmutable` (`Annee.php:55`) → `TypeError` latent si une année non activée est passée. Pour du code neuf sans appelant externe, paramètre trompeur évitable.

- **M2 (Claude, mineur) — RETENU, confirmé.** `ReglagesAdministration::afficher()` (`ReglagesAdministration.php:68`) lève `\LogicException` sur capacité absente, au lieu de `wp_die()` (convention WordPress pour un refus d'accès). Une exception non rattrapée donne une page d'erreur fatale.

- **M3 (Claude, mineur) — RETENU.** Source [5] (alignement de facturation, `sources/review-2026-11-22.json`) : extrait stocké tronqué, ne montre pas littéralement l'exemple « 6 avril → 1er mai » cité dans la proposition. URL joignable, donc acceptable mais à compléter.

- **C05-02 (Codex, mineur) — RETENU.** `production/C-05/proposition.md:47` : l'affirmation sur le traitement particulier des renouvellements anticipés (`woocommerce_subscription_payment_complete`) renvoie à [4], mais aucun extrait conservé pour cette source ne porte sur ce hook. Doute documentaire, pas constat d'erreur.

> M3 et C05-02 sont **deux lacunes de citation distinctes** (sources [5] et [4]), pas un doublon : traiter les deux.
