### R2 — Important — vu par Codex seul, **confirmé par relecture du code**. `Inventory.php:84` + `a19/Inventory.php:33,40`.

Pour une passerelle **sans lecteur local A-27** (absente de `Inventory::REFERENCES`, qui ne couvre que `stripe`, `stripe_sepa`, `paypal` — ex. `ppcp-gateway`), A-27 n'a aucune métadonnée propre et s'en remet au verdict de présence d'A-19 (`reference`, ligne 84). Or `a19/Inventory.php:33,40` renvoie `absent` pour un champ déclaré par `woocommerce_subscription_payment_meta` dont la `value` est **non scalaire**. Déroulé dans `Analysis::reference()` : `$present = (bool)$ids || reference !== 'absent'` = `false` (ligne 123) → l'abonnement est **exclu** (ligne 150), ni compté `automatic`, ni en `relations`.

C'est une présence **indéterminée** (champ déclaré mais illisible) traitée en **absence prouvée**. Cela contredit la règle du brief et du README ligne 43 : « ce qu'on ne sait pas lire est illisible, jamais absent ». **Avis : réel, important.** Portée étroite (passerelle hors `REFERENCES`, sans jeton, champ déclaré non scalaire), mais `ppcp-gateway` — le PayPal moderne — est justement hors `REFERENCES` : cinq références opaques peuvent produire zéro `automatic` au lieu de cinq `illisible`. Matériel pour un décompte qui alimente une décision bancaire. Je l'avais manqué : mon rapport a validé « illisible jamais absent » sans dérouler ce chemin A-19.

### R3 — Important — vu par Codex seul, **confirmé par relecture du code**. `Analysis.php:103-116` vs README ligne 46.

Le README ligne 46 promet : « contradiction entre lien explicite et référence : illisible et liaison indéterminée, sans choix d'un instrument ». Le code ne le fait pas quand une référence unique pointe un jeton **différent** du lien explicite. Déroulé : lien explicite vers le jeton B (ids = [B]), référence `_stripe_source_id` correspondant au jeton A (A ≠ B, même compte/passerelle). Ligne 106 non déclenchée (`count($refs)==1`, `count($matches)==1`). Ligne 109 fausse (A ∉ ids). Chute en ligne 114 : repli par passerelle → `mandat_sepa` (ou `accord_paypal` côté PayPal), liaison `unknown`. Un instrument déterminé est publié malgré deux références contradictoires. **Avis : réel, important.** Le code diverge de son propre défaut documenté. Le repli ligne 114-116 reste **légitime** pour la référence seule sans lien (PayPal sans jeton = `accord_paypal` attendu) ; la correction doit viser la seule contradiction (ids non vide + référence qui ne résout pas vers un jeton lié).
