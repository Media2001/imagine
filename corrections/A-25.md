## 2. Points vus par un seul, avec l'avis du fusionneur

- **[Codex, I-1 — retenu] Faux négatif possible sur les tables de messages inconnues** (`Inventory.php:85-87`). Le détecteur écarte toute table portant une colonne nommée `submission_id`. L'intention (commentaire ligne 84) est d'éviter les tables-filles de détail/méta qui compteraient un message plusieurs fois. Mais l'exclusion porte sur la **présence du nom de colonne**, pas sur son **rôle**. Une table inconnue à un message par ligne, dont `submission_id` serait la **clé primaire** (+ `form_id`, `message`/`response`, une colonne de date), satisfait tous les autres critères mais est écartée. Sans autre table de formulaires : `other_tables = 0`, total nul, là où le brief impose le classement sous « autre ».
  - **Avis du fusionneur : réel, je tranche pour Codex.** J'avais donné « Conforme » sans voir ce point ; Codex l'a dérivé du code, il a raison. Le sens de l'erreur est le mauvais pour un registre RGPD : **sous-compter** ce que le site garde est plus grave que **sur-compter**. Or le commentaire ligne 84 montre un choix de conception optimisé contre le sur-comptage (double compte des tables-filles), c'est-à-dire vers le mauvais côté pour ce lot. Le correctif est **peu coûteux et précis** : la requête `information_schema.COLUMNS` (`Inventory.php:80`) peut remonter `COLUMN_KEY` ; un `submission_id` en `PRI` (clé primaire → un message par ligne) doit compter, un `submission_id` simple avec clé `id` propre (table-fille) doit rester exclu. Le contre-exemple est **fictif, non démontré sur une base réelle ni sur un vrai schéma d'extension** ; j'en tiens compte pour la sévérité, mais le point reste à corriger.
- **[Codex, lacune de test — retenu] `seed.php:38`** ne crée qu'une table inconnue à clé `id` (`a25_unknown_entries`), qui satisfait exactement l'heuristique. Elle ne couvre pas le cas `submission_id` en clé primaire. **Avis : réel et confirmé.** Mon premier rapport a loué la couverture des cas limites sans voir ce trou ; Codex a raison. Le cas nominal vert masque le faux négatif de I-1.
- **[Claude, rejeu PHP — retenu] Preuve que Codex n'a pas pu obtenir.** `rejouer.ps1` sans argument, conteneur jetable, réseau coupé, dépôt en lecture seule : `REJEU : 1126 tests, 35550 assertions, 0 échec — PASS` ; A-25 = 15 contrôles, 0 échec. **Avis : à conserver — cela lève le doute de Codex.** Côté Codex, `verify.py` renvoie 0, mais `unittest` donne 3 erreurs et `matrix.py` code 1 : ces échecs sont **environnementaux** (Windows `PermissionError`/`WinError 5` sur les répertoires temporaires ; `DOCKER_IMAGE_FAILED`, pas de Docker dans son environnement), **non imputables au code A-25**. Le rejeu complet « non confirmé » chez Codex **est confirmé** par le run conteneurisé de Claude.
- **[Claude, Mineur — retenu] `clear_messages_after_import`** (`Inventory.php:112`, `report.py:40`) : constante `true` imposée aussi par la projection ; l'outil ne la mesure pas sur la copie (il ne rejoue pas l'import). **Avis : réel, mineur.** C'est un avertissement éditorial permanent, pas une mesure propre à la copie ; à étiqueter comme tel dans la sortie pour que Ced ne le lise pas comme un constat mesuré. Pas de changement de logique.
- **[Claude, Mineur — retenu] `SOURCES.md`** donne les adresses mais pas la **phrase exacte** citée, exigée par la grille §6 pour chaque affirmation sur une extension. **Avis : réel, mineur.** Ajouter la citation littérale du schéma Fluent Forms (`fluentform_submissions`/`created_at`).

## 4. Instructions pour Hermès (numérotées)

1. **(Important, I-1) Corriger le détecteur de tables de messages inconnues** (`Inventory.php:85-87`). Ne plus exclure une table sur la seule présence d'une colonne `submission_id`. Distinguer le **rôle** de la colonne : remonter `COLUMN_KEY` dans la requête `information_schema.COLUMNS` (`Inventory.php:80`) et ne conserver l'exclusion que lorsque `submission_id` est une référence (table ayant sa propre clé `id`), pas lorsqu'il est la **clé primaire** de la table. Objectif : un `submission_id` en `PRI` + `form_id` + `message`/`response` doit compter sous « autre », sans publier le nom. En cas de structure encore ambiguë, émettre une **valeur fermée de « couverture indéterminée »** plutôt qu'une absence certaine (jamais de zéro silencieux). Conserver la protection contre le double compte des tables-filles de détail/méta.
2. **(Important, test lié à I-1) Compléter le banc** (`seed.php:38`). Ajouter une table native inconnue à **un message par ligne dont `submission_id` est la clé primaire**, avec cinq entrées, pour vérifier d'un coup : le comptage sous « autre », l'absence de double compte, et l'absence de zéro silencieux. Garder aussi un cas de vraie table-fille (clé `id` propre + `submission_id` référence) qui, lui, doit rester exclu.
3. **(Mineur) Étiqueter `clear_messages_after_import`** dans la sortie comme « avertissement éditorial permanent, non mesuré sur la copie inspectée » (déjà dit au README/rapport ; le rendre explicite dans le JVL de sortie). Pas de changement de logique.
4. **(Mineur) Ajouter à `SOURCES.md`** la phrase exacte de la documentation Fluent Forms (`developers.fluentforms.com/database/`) justifiant `fluentform_submissions` / `created_at`, comme l'exige la grille §6.
