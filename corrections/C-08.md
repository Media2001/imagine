# Fusion C-08 — Le paywall branché sur l'article

Date : 23/11/2026. Fusionneur : Claude. Sources : `relectures/C-08/claude.md`, `relectures/C-08/codex.md`.
Divergences tranchées en relisant le code (`wp/plugins/imagine-site/Paywall.php`, `imagine-site.php`, `wp/outils/demo/c08-seed.php`, `b00-seed.php`, `wp/tests/demo/c08-regression.py`, `b01_html.py`) et le cahier (`docs/cahier-des-charges-v3.1.txt` §3.8, §3.9, §4.4, lignes 825–837).

**Preuve.** Les deux relecteurs confirment la concordance des empreintes SHA-256 entre le code relu et les reçus (Codex : 16 empreintes source de `verification-finale.json` ; Claude : reçus relus à zéro échec). Le code présent est bien celui qui a été testé.

**Rejeu.** Aucun n'a rejoué la suite complète. Claude : `docker`/`composer test` non approuvés ; recettes visant le site `imagine-test-demo`, hors droits du relecteur. Codex : a exécuté localement `test_c08_scope.py` (5 réussis) et `test_b0*.py` (7 réussis, **1 erreur d'import `bs4`**, voir C08-02) ; les recettes HTTP/runtime/pannes/idempotence accèdent au site ou réécrivent des preuves, hors droits. Les **425 contrôles** annoncés restent des résultats de livraison, pas une exécution indépendante reproduite. Le rejeu réel reste dû.

## 1. Points retenus par les deux relecteurs

- **Les quatre attendus du brief sont présents.** Adaptateur `Paywall::decision()` → moteur C-06 (`Moteur::decider`) + vérificateur robots C-03 ; point de sortie `imagine_article_body()` et les quatre gabarits (`connexion`, `abonnement`, `regularisation`, `decouverte_epuisee`) ; étanchéité page/REST/flux/extrait/partage/oEmbed/embed, XML-RPC coupé ; en-têtes privés `no-store`. Conforme.
- **Fermeture par défaut effective.** Le `catch` renvoie `complet=false` (`Paywall.php:50`) ; confirmé sur page/REST/flux/oEmbed par les reçus de pannes.
- **Exactitude métier nominale.** Les deux ont déroulé à la main R-25 (abonné actif), R-26 (anonyme), grâce (`on-hold` + `paused` + fenêtre explicite), compte sans droit, faux robot, et les bornes temporelles (`now < graceEnd`, `instant >= fin`) : résultats conformes. Changement d'année sans calcul spécial (dates complètes).
- **Sécurité / données.** Aucun secret, aucune donnée réelle ; comptes `@example.org` ; mots de passe hors dépôt. Échappement `esc_html`/`esc_attr`/`esc_url`, `wp_json_encode` avec `JSON_HEX_*`, écritures de métadonnées sous `auth_callback`. REST : rendu ET brut supprimés, `password` retiré, `protected=true`. `sanitizePosts` clone sans contaminer le cache objet. Aucune fuite du corps réservé constatée dans les fichiers et réponses archivés.
- **Doctrine « standard d'abord ».** Objets natifs Memberships/Subscriptions, pas de table de droits parallèle, hooks seulement, bibliothèques closes C-06/C-03 ni modifiées ni activées. Conventions §5 (`strict_types`, namespace `Imagine\`, préfixe `imagine_`, textes traduits, README). Conforme.
- **Limites honnêtement déclarées.** PDF non fermé par C-08, robot Internet vérifié R-27 non démontrable hors ligne (DNS coupé), parcours complets R-29/R-30, découverte complète, tunnel d'achat : hors périmètre et explicités, non présentés comme prouvés.
- **Verdict commun : À corriger.** Aucun défaut classé **bloquant** établi dans le périmètre vérifié : les fixtures livrées ne fuient pas et le minimum du brief (4 situations) est prouvé.

## 2. Points vus par un seul relecteur — avis du fusionneur

### Vus par Codex seul (manqués par Claude) — tous confirmés au code

- **[Important — C08-01] Ouverture par le booléen natif mal interprétée.** `Paywall.php:31` n'accepte que les chaînes `'0'` / `'1'`. Or `imagine_reserve` est déclaré `type => 'boolean'` (`imagine-site.php:63`). Une écriture native `false` est stockée `''` (et `true` → `'1'`) : lue `''`, elle échoue `in_array(..., ['0','1'], true)`, lève l'exception et renvoie `adaptateur_indisponible` → article fermé, même paru et valide. **Retenu.** Précisions du fusionneur : (a) le défaut **ne se déclenche pas sur la démo**, car les deux seeds écrivent explicitement les chaînes `'0'`/`'1'` (`b00-seed.php:140`, `c08-seed.php:91`) ; (b) il **échoue côté fermé** (pas de fuite) ; (c) c'est néanmoins un vrai défaut du contrat de données qui mordrait en rédaction réelle (un article ouvert à la main via le champ booléen serait paywallé à tort). Claude avait validé « l'absence de métadonnée n'ouvre pas » sans voir l'arête du `false` enregistré.
- **[Important — C08-02] Dépendance `bs4` manquante pour rejouer la non-régression.** `c08-regression.py:12` fait `from b01_html import validate_html` ; `b01_html.py:9` importe `from bs4 import BeautifulSoup` (et `html5lib` ligne 8). Or `production/B-01/validation/dependencies.json` ne liste que `html5lib` et `webencodings` — pas `beautifulsoup4`. L'import échoue (`ModuleNotFoundError: No module named 'bs4'`, constaté par Codex à l'exécution) et empêche la recette C-08 de démarrer avec les seuls prérequis livrés. **Retenu.** Ne démontre pas un défaut du rendu HTML ; c'est un prérequis de rejeu incomplet.
- **[Mineur — C08-03] Type JSON-LD contraire au cahier.** `Paywall.php:235` émet `'@type' => 'Article'`. Le §3.9 demande expressément `NewsArticle` (`docs/cahier-des-charges-v3.1.txt:831`). `isAccessibleForFree`, `hasPart` et le sélecteur sont présents, le corps n'est pas inclus ; c'est un écart au contrat **non signalé**, pas une invalidité générale. **Retenu.** Correction simple ; la recette de partage ne vérifie pas encore ce champ.

### Vus par Claude seul (manqués par Codex) — confirmés au code

- **[Important] Recherche interne non fermée par C-08.** Aucune garde `pre_get_posts` / `posts_search` dans `register()`. Le corps réservé reste dans `post_content` en base ; l'appariement SQL de `/?s=<témoin>` peut faire remonter l'article réservé à l'anonyme (titre + extrait), révélant que le corps caché contient le terme — même si `sanitizePosts` masque ensuite le texte. Aujourd'hui l'article n'apparaît pas **seulement** parce que la fixture garde un `post_password` natif (`c08-seed.php:89`), que le modèle déclare simple repli (« jamais un droit de lecture »). Le §3.9 ligne 835 nomme explicitement « la recherche interne » dans l'étanchéité exigée côté serveur. **Retenu — voir §3 (divergence).**
- **[Important] `decision()` recalculée sans mémoïsation.** Rappelée par `sanitizePosts` (`:175`), `content` (`:191`), `rest` (`:197`), `post_password_required` (`:259`), chacune relançant les requêtes Memberships/Subscriptions et la vérification robots. Coût N× sur une archive ou une page de recherche. Risque direct sur les seuils de réception du chapitre 5 (Lighthouse mobile, LCP). **Retenu.**
- **[Mineur] Déterminisme des deux couches.** Sans mémoïsation, `sanitizePosts` et `imagine_article_body` recalculent l'instant indépendamment ; à la seconde d'une bascule d'échéance ils pourraient diverger. La mémoïsation lève ce risque. **Retenu.**
- **[Mineur] Portée du cache trop large.** `cacheHeaders` + `DONOTCACHEPAGE` posés sur **toutes** les réponses (`wp_headers` et `rest_post_dispatch` à `PHP_INT_MAX`), y compris les pages ouvertes. Le §4.4 demande que le cache *distingue* connectés et anonymes, pas qu'il soit désactivé partout. Sûr pour la démo ; à resserrer au lot cache. **Retenu, à tracer.**
- **[Mineur] Contournement par `get_post()`.** L'expurgation passe par `the_posts` ; un futur `echo get_post($id)->post_content` la contournerait (cache objet intact, voulu). Thème actuel sûr. **Retenu, à documenter comme règle.**
- **[Mineur] Réglages du moteur non alimentés.** L'adaptateur ne lit aucune option vers `Acces\Reglages` : le moteur tourne sur ses valeurs par défaut. Sans effet dans ce lot (futur/PDF hors périmètre) ; à brancher avec C-10. **Retenu, à tracer.**
- **[Mineur] Recettes B-00/B-01 historiques laissées rouges.** « Exactement quatre articles », « mot de passe ⇒ complet » deviennent fausses sur le site augmenté ; `c08-regression.py` les remplace proprement, mais l'ancienne suite afficherait du rouge et serait prise pour une régression. **Retenu.**
- **[Mineur] Lacunes de couverture.** (a) Le mappage `rights()` traduit beaucoup d'états (`suspendu`, `expire`, `virement_non_valide`, `on-hold` sans fenêtre, `paused` sans abonnement, rôle équipe) ; seuls `actif`, `grace`, `sans-droit` sont éprouvés de bout en bout. (b) La recherche n'est testée qu'avec le terme public « C08 » (`c08-verifier.py:107`), jamais avec le témoin. **Retenu** (la seconde renforce le point recherche du §3).

## 3. Désaccords

- **Étanchéité de la recherche interne.** Claude la tient pour non fermée par C-08 (important, possiblement bloquant au regard du §3.9). Codex conclut « aucune fuite du corps réservé établie » et juge les protections effectives, notant que la recherche native « peut exclure » un article qui conserve son mot de passe B-00.
  **Arbitrage du fusionneur : Claude a raison sur le fond.** Le §3.9 ligne 835 exige explicitement l'étanchéité de « la recherche interne » côté serveur ; `register()` n'ajoute aucune garde ; l'étanchéité actuelle repose sur le `post_password` natif, déclaré simple repli. Le constat « pas de fuite » de Codex porte sur les réponses archivées et ne couvre **pas** le vecteur recherche-par-témoin, jamais testé (`c08-verifier.py:107` n'utilise que « C08 », un terme public). Il n'y a donc pas conflit de constat : Codex n'a pas sondé ce vecteur, Claude l'a vu. Classé **important**. Caractère bloquant : à trancher par Ced (§5, question 1).
- **Aucun autre désaccord.** Ailleurs les rapports sont complémentaires, pas contradictoires : Codex a vu C08-01/02/03 que Claude a manqués ; Claude a vu la recherche, la mémoïsation et le cache que Codex a manqués. Les deux convergent sur « À corriger » et sur l'absence de bloquant établi.
