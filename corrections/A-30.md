## 2. Points vus par un seul relecteur — avis du fusionneur

### 2.1 A30-C01 (Codex) — la suite Python n'est pas rejouable sous Windows sans `TMPDIR`. **Retenu, important.**

`wp/tests/a30/test_core.py:32`, `test_cli.py:18`, `test_boundary.py:19` et `test_verify.py:19` créent leur répertoire de travail avec `tempfile.TemporaryDirectory(..., dir=os.environ['TMPDIR'])`. `TMPDIR` est une convention Unix ; Windows définit `TEMP`/`TMP`, pas `TMPDIR`. Sur une session Windows propre, l'accès `os.environ['TMPDIR']` lève `KeyError` dans le `setUp` de chaque classe qui crée un dossier. Codex le reproduit : `python -m unittest discover -s wp/tests/a30`, en UTF-8 puis en cp1252, donne **25 tests, 22 erreurs `KeyError: 'TMPDIR'`** dans chaque contexte ; seuls les trois tests sans dossier temporaire passent.

J'ai relu le code et je confirme le mécanisme :
- Les quatre occurrences sont bien `dir=os.environ['TMPDIR']`, sans défaut ni garde (grep confirmé sur `wp/tests/a30`).
- `matrix.py:40` prépare l'environnement du rejeu Windows avec `env = {**os.environ, 'PYTHONIOENCODING': ..., 'PYTHONUTF8': ..., 'PYTHONDONTWRITEBYTECODE': '1'}` — **il n'ajoute pas `TMPDIR`**. La matrice hérite donc du `TMPDIR` ambiant de la machine parente. Sur le poste d'Hermès la variable était présente (le paquet scellé est vert) ; sur une machine propre elle ne l'est pas. Le sceau ne contredit pas C01 : **il le masque**, en figeant un résultat obtenu sous un environnement préconditionné.
- Le code de production (`confine.py:74`) n'utilise **pas** `TMPDIR` — il crée son dossier privé sous `source.parent`. Le défaut est strictement dans le harnais de test, pas dans l'outil.

Le brief est explicite (ligne 27) : « **Suite Python rejouable sous Windows (cp1252).** » Une suite qui lève `KeyError` sur 22/25 tests d'une session Windows propre, dans les deux encodages, ne satisfait pas cette exigence écrite. C'est donc bien un défaut **important**, pas mineur.

**Pourquoi Claude l'a manqué, dit clairement (doctrine CLAUDE.md).** Ma relecture s'est appuyée sur la commande autorisée `rejouer.ps1` (sortie *PASS*) et sur le sceau du paquet. Or `rejouer.ps1` exécute la **suite PHP en conteneur Docker** (`t01/executer.php`) plus les tests purs des outils ; le lecteur A-30 inclus dans les « 9 paquets vérifiés » est `verify.py`, qui **re-contrôle le paquet scellé**, il ne rejoue pas la matrice Python Windows en direct. Aucune des deux voies que j'ai empruntées ne lance la suite `test_*.py` d'A-30 sur Windows à neuf. J'ai pris pour acquis, à tort, le « sonde les encodages réels » de `matrix.py` et la rejouabilité annoncée. **Sur ce point Codex a vu ce que j'ai manqué** : il a lancé la suite Python indépendamment et a buté sur le défaut réel. Je remonte le point à mon rapport absent et je l'inscris **important**.

Ce n'est pas bloquant : le classement métier, la lecture seule et le confinement restent corrects, et aucune fuite de donnée n'en découle. Mais la correction est due avant clôture, car la rejouabilité Windows est une exigence écrite du brief et le trou touche presque toute la suite.
