## 2. Points vus par un seul relecteur, avec avis du fusionneur

### Vus par Codex seul — confirmés après relecture du code (Claude les a manqués)

**P1 — Bloquant — Une extension à seulement `desactiver` perd ses fichiers si elle partage un dossier avec une extension `retirer`.**
- `clean.py:155` : `need(not any(... plugin_action(plan,n)=='garder' ...),'A05_SHARED_PLUGIN_DIRECTORY',base)`. La garde ne refuse que le voisin **`garder`**. Un voisin `desactiver` passe.
- Conséquence : `operations` produit un `rmtree` du dossier entier (`clean.py:157`, exécuté `:245`). Le plugin `desactiver` — dont l'action signifie explicitement « désactiver mais garder les fichiers » (brief §1, `nettoyer.md:9`) — perd ses fichiers. Vaut aussi s'il était déjà inactif.
- **Avis** : réel et grave. C'est exactement la classe de dégât que l'outil existe pour empêcher : détruire ce qui n'a pas été nommé pour destruction. `nettoyer.md:34` ne cite que « dossier partagé contenant un autre fichier principal **gardé** » — le cas `desactiver` a simplement été oublié. **Retenu bloquant.**

**P2 — Bloquant — Une dépendance déclarée en en-tête `// ` ou `# ` est ignorée ; son extension peut être retirée.**
- `clean.py:123` (lecture `Plugin Name:`) accepte les préfixes `/*`, `*`, `//`, `#`. `clean.py:126` (lecture `Requires Plugins:`) n'accepte que `*`. Asymétrie interne.
- Un plugin gardé avec `// Plugin Name: Kept` + `// Requires Plugins: base` est inventorié `requires:[]` (`clean.py:131`). Le refus obligatoire `A05_DEPENDENCY` (`clean.py:67-70`) ne se déclenche pas → `base` peut être retiré.
- **Avis** : réel. WordPress (`get_file_data`, préfixes `[ \t/*#@]*`) lit ces en-têtes ; le code est plus strict que WordPress **et** que sa propre regex `Plugin Name`. C'est un refus de sûreté obligatoire (brief §Règles, `nettoyer.md:34`) qui tombe ouvert. Déclencheur étroit (style d'en-tête inhabituel, et seulement si la dépendance est par ailleurs retirée), mais un refus de sûreté qui échoue **ouvert** est bloquant par principe. Claude n'avait noté qu'une « limitation d'heuristique » mineure et générale, sans voir l'asymétrie concrète entre les deux regex. **Retenu bloquant.**

**P3 — Important — Un dossier `uploads` gardé ne protège pas ses descendants.**
- `clean.py:164-165` : la garde `A05_UPLOAD_KEEP_CONFLICT` ne teste que `kept['path']==row['path']` ou `kept['path'].startswith(row['path']+'/')` — c'est-à-dire un **descendant gardé** bloquant la suppression de son parent (sens documenté `nettoyer.md:12`). Le sens inverse manque : `archive: garder` + `archive/2020: supprimer` n'est pas refusé et produit une suppression de `archive/2020`.
- **Avis** : réel. Contredit `nettoyer.md:13` (« une règle `garder` l'emporte sur une suppression recouvrante »). Pas de perte silencieuse au même titre que P1 (l'opérateur a nommé `archive/2020`), mais le plan est contradictoire et la doctrine tranche pour `garder`. L'outil doit refuser le conflit, comme il le fait déjà dans le sens miroir. **Retenu important.**

### Vus par Claude seul — retenus mineurs

- **M1 — Sortie à blanc muette sur un nom planifié mais absent du site** (`clean.py:149`, `continue`). Un nom présent au plan mais absent du site est ignoré sans trace dans le JSON à blanc. Gêne la relecture de Ced. **Avis** : mineur, utile. Décision technique, défaut ci-dessous.
- **M2 — Barrière d'écriture `active_plugins` sensible à la forme exacte de l'`UPDATE` du cœur WordPress** (`bootstrap.php:16`). En cas d'évolution du cœur, échoue **fermé** (`A05_DEACTIVATE_READBACK`), jamais en perte de données. **Avis** : fragilité à surveiller, pas un défaut. Mineur.
- **M3 — Heuristiques dépendance/passerelle limitées au périmètre connu.** Partiellement recoupé par P2, qui en donne un cas concret et corrigible. **Avis** : la partie « dépendance » devient P2 (bloquant) ; la partie « passerelle sans marqueur » reste une limite documentée, mineure.

## 3. Désaccords

**Verdict : « Conforme » (Claude) contre « À corriger » (Codex).**

Tranché pour **À corriger**. Claude a vérifié que le formulaire livré (tout `garder`) est sûr et a déroulé les chemins nominaux et un jeu de refus — tout cela est exact. Mais il n'a pas construit les **plans de conflit adverses** (voisin `desactiver` partageant un dossier, en-tête `//`, ancêtre gardé + descendant supprimé). Codex les a construits et a touché trois trous de garde réels. L'outil est un exécuteur de plan **général** ; le brief impose ces refus pour **tout** plan, pas seulement pour le formulaire conservateur livré.

Nuance importante, à ne pas perdre : **aucun des trois défauts ne peut se déclencher sur `plan-imagine.exemple.json`** (aucun `retirer`, aucun `supprimer`, tout `garder`). Le lot ne met donc aujourd'hui aucune donnée réelle en danger. Mais les garanties de sûreté sont incomplètes et doivent l'être **avant** qu'un plan de retrait soit un jour exécuté. D'où « À corriger » et non « À refaire » : l'architecture est saine, trois gardes sont à compléter.

Sur les tests : la preuve `3f1d3e3ce8f2` (93 contrôles, 0 échec) est honnête mais **ne couvre pas** ces trois conflits. Codex a reproduit P1/P2/P3 par trois assertions en mémoire (trois échecs). Ni Claude ni Codex n'a pu rejouer la suite native Docker (écriture `production/` interdite ; WSL `E_ACCESSDENIED` côté Codex). La suite PHP globale T-01 (1012/34006) relancée par Claude reste verte : non-régression du reste du dépôt confirmée, hors périmètre A-05.

## 4. Instructions pour Hermès (numérotées)

1. **P1 — Fermer la garde de dossier partagé.** Dans `clean.py:155`, refuser `A05_SHARED_PLUGIN_DIRECTORY` dès qu'un autre fichier principal du même dossier a une action **autre que `retirer`** (donc `garder` **ou** `desactiver`), en nommant le conflit. Variante acceptable si plusieurs `retirer` partagent un dossier : terminer leurs désactivations et désinstallations explicites, puis supprimer le dossier une seule fois ; sinon, refuser. Ajouter les tests : voisin `desactiver` actif et inactif, dans les deux ordres du plan.
2. **P2 — Aligner la lecture d'en-tête.** Dans `clean.py:126`, accepter les mêmes préfixes de commentaire que `Plugin Name:` (`clean.py:123`) : `/*`, `*`, `//`, `#` — idéalement la classe WordPress `[ \t/*#@]*`, sans charger l'extension. Ajouter les tests : extension gardée déclarant `// Requires Plugins:` puis `# Requires Plugins:` → `A05_DEPENDENCY:<dep>` au retrait **et** à la désactivation de la dépendance.
3. **P3 — Rendre la garde uploads symétrique.** Dans `clean.py:164-165`, refuser aussi quand la cible de suppression est un **descendant** d'un chemin gardé : ajouter le test `row['path'].startswith(kept['path']+'/')`. Ajouter les tests : ancêtre `garder` + descendant `supprimer`, dans les deux ordres des règles.
4. **Refaire les preuves.** Après P1–P3, ajouter ces trois cas de conflit aux tests du lot, puis régénérer la preuve scellée (`3f1d3e3ce8f2` → nouvelle empreinte). La preuve actuelle est honnête mais ne couvrait pas ces conflits ; « 93 contrôles, 0 échec » ne vaut pas sans ces cas.
5. **M1 (défaut technique, appliquer sans attendre).** Dans la sortie à blanc, journaliser les noms du plan absents du site en ligne informative sans opération (ex. « nommé, absent »). Facilite la relecture de Ced. Claude arbitre après coup.
